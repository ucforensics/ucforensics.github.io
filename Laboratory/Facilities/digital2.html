LAB 01Digital Identity and Instruction Fidelity⌄

Objective

To appreciate how digital identifiers (QR codes) support classroom workflows and how strict formatting matters in computer- based systems.

Materials and equipment

Internet-connected device, Lo Card, Access to a printer, QR code scanner app, Scissors, Sticker paper

Procedure

1. Prepare your Lo Card and sticker paper. 2. Using an internet-connected device, go to the QR code generator website: https://www.qrcode-monkey.com 3. Select **Text** as the QR code content type. 4. Set the quality to **High Quality** (move the quality slider to high). 5. In the text field, encode your name using this exact format: **LastnameFirstnameM**. a. Do not use spaces. b. Use proper capitalization: the first letter of each name segment must be uppercase. c. If you have two or more given names, capitalize the first letter of each given name segment. d. Examples: * GatesWilliamH OR * DelaCruzMariaMercedesQ 6. Double-check your entry for accuracy. Remember that in computer systems, even a one-character error can cause failure (e.g., syntax errors and mismatched identifiers). 7. Click **Create QR Code** 8. Download the generated QR code as a **PNG** file. 9. Rename the downloaded file to match your encoded name exactly (e.g., **GatesWilliamH.png**). 10. Upload the renamed PNG file to the course repository using the platform or instructions provided by your instructor. 11. Resize the QR code image to **5.08 cm × 5.08 cm** (2 in × 2 in) before printing. Ensure the QR code remains clear and not blurred or stretched. 12. Print the resized QR code on sticker paper. 13. Cut the printed QR code neatly (if needed), then stick it onto your Lo Card. 14. Bring your QR-coded Lo Card to every class for the entire term. When you recite and answer correctly, your instructor may scan your QR code to record participation or points. 15. Install a QR code scanner app on your phone. Verify it works by scanning your printed QR code. Keep the scanner app available for future class instructions.

Guide questions

1. Why is strict name formatting (capitalization and no spaces) important when generating and using digital identifiers like QR codes? 2. What classroom or laboratory processes can be improved by using QR-coded recitation cards, and what risks must be managed (e.g., misidentification or privacy concerns)?

LAB 06Signal Shielding Simulation⌄

Objective

To design and build a simple Faraday cage and evaluate its effectiveness in reducing radio-frequency signals to illustrate basic evidence isolation concepts in digital forensics.

Materials and equipment

Aluminum foil, Box, (conductive) Tape, Glue, Marker, Ruler, Scissors, Smartphone

Procedure

1. Select a box that can fully enclose a smartphone and can be closed securely (with a lid or flap). 2. Inspect box for openings, seams, or gaps where signals can leak 3. Cut aluminum foil pieces large enough to line the inside surfaces of the box (bottom, sides, and lid). 4. Apply glue to the interior surfaces of the box, then line the inside with aluminum foil. 5. Ensure foil pieces overlap at edges and corners so that the lining forms a continuous conductive layer. Do not leave exposed gaps. 6. If available, use conductive tape to secure foil overlaps and reinforce seams (especially around corners and the lid edges). 7. Line the inside of the lid (or flap) with aluminum foil and ensure it overlaps with the foil lining on the box body when closed. 8. Build a secure closure: a. Add a foil “lip” or overlap area around the rim of the box so that, when closed, foil touches foil. b. Reinforce the closure with conductive tape if available. 9. Allow glue to set so the foil does not peel off during testing. 10. Testing phase (simulation): a. Choose one group member’s smartphone for the test and ensure everyone has the phone number. b. Keep the phone powered on and connected to the network (do not enable airplane mode). c. Place the smartphone inside the Faraday cage and close the lid. d. Other groups will attempt to call the phone number. 11. Record the result of the call attempts (e.g., rings normally, delayed ring, goes to voicemail, call fails) and note any differences across repeated trials. 12. Improve and re-test if needed by sealing gaps, increasing foil overlap, or reinforcing the lid seam, then repeat Step 10 and compare results.

Guide questions

1. What design features most affected your Faraday cage performance (e.g., gaps, seams, lid overlap, foil continuity), and why? 2. Why does a Faraday cage help in certain digital forensics situations, particularly in preventing remote access, wiping, or incoming network activity? 3. If the phone still received calls, what specific modifications would you implement to improve shielding, and what is your technical basis for each change?

LAB 08Command Prompt File Creation, Hashing, and File Comparison⌄

Objective

To use basic Command Prompt commands to create files in a specified directory, generate cryptographic hashes, and compare hashes to verify file integrity.

Materials and equipment

PC, Command Prompt or Windows Terminal

Procedure

1. Open **Command Prompt**: press **Windows + R**, type **cmd**, then press **Enter**. 2. Create a working directory in a specified location, for Desktop: a. Type: `cd %USERPROFILE%\Desktop` then press **Enter**. b. Type: `mkdir DF_LAB` then press **Enter**. c. Type: `cd DF_LAB` then press **Enter**. 3. Create a text file using the command line: a. Type: `echo this is a file > file1.txt` then press **Enter**. b. Confirm the file exists by typing: `dir` then press **Enter**. 4. Create a second file to compare: a. Type: `copy file1.txt file2.txt` then press **Enter**. b. Confirm both files exist using: `dir` then press **Enter**. 5. Generate hashes for both files using a built-in Windows tool (CertUtil): a. Type: `certutil -hashfile file1.txt SHA256` then press **Enter**. b. Copy the SHA-256 hash value exactly as shown. c. Type: `certutil -hashfile file2.txt SHA256` then press **Enter**. d. Copy the SHA-256 hash value exactly as shown. 6. Compare the hash values: a. If the hashes match, the files are identical at the byte level. b. If the hashes do not match, the files differ. 7. Modify one file to demonstrate integrity change: a. Type: `echo additional text >> file2.txt` then press **Enter**. b. Hash file2 again using: `certutil -hashfile file2.txt SHA256` then press **Enter**. c. Compare the new hash to the original hash of file1. 8. Optional file comparison using built-in tools: a. Type: `fc file1.txt file2.txt` then press **Enter**. b. Observe the reported differences. 9. Save your results: record the commands used, the hash values generated, and your observations on whether the files matched or differed.

Guide questions

1. Why is hashing used in digital forensics, and what does it prove when two hash values match exactly? 2. After you edited file2.txt, what happened to its hash value, and why is this expected? You may copy the hash values to support your answer. 3. How do hashing and file comparison tools (e.g., `certutil` and `fc`) support chain of custody and evidence integrity?
